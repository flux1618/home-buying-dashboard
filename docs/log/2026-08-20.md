
## Household gross slider widened to $0–$10M

Requested change: the income slider spanned $150K–$600K, now $0–$10,000,000 (step $1,000).

The range itself is one attribute. What it cost was the two edges it made reachable:

- **$0 income.** `piti / (inc/12)` printed `Infinity%` for front-end DTI. At no income a DTI
  is undefined, not infinite -- there is no share of nothing -- so the KPI reads `—` and the
  max-price card says so explicitly. `analyzer/core/cost.py` already raises rather than
  dividing on this input; the page now refuses it for the same reason instead of rendering a
  number that looks like a bug.
- **$10M income.** DTI stops binding long before any Spartanburg price does, so
  `solveMaxPrice` returned its bracket edge and `renderMaxPrice` printed it as a solved
  maximum. It also used `down + 5000000`, which is not the engine's `_SOLVER_CEILING`
  ($5,000,000 absolute) -- two solvers disagreeing about where the search stops. The page
  now uses the same constant, labels the value `$5,000,000+`, and says "search ceiling
  reached — not a solved maximum", which is the same thing the engine puts in `notes`.

`tests/test_max_price_page.py` covers both edges under node and asserts the JS
`SOLVER_CEILING` literal equals `cost._SOLVER_CEILING`, so the two cannot drift apart
silently. Suite 897 -> 904.

Verified in Chromium at 1600px and 390px at $0 / $12K / $406K / $10M: no clipped labels,
no horizontal overflow, monotonic answers below the ceiling.
