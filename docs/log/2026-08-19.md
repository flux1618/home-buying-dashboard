# 2026-08-19 — From a page with a calculator to a system with an engine

**Commits:** `f136262` … `7634f07` (14)

**ADRs written:** 0001–0008

## Where the day started

A single static page: `index.html`, `app.js`, and a `data.json` of market data. It looked
finished. It modeled affordability, rent-versus-buy, submarket scores, and had a property
scorer where you typed in a few facts and got a 0–100 number back.

The problem with it was not visible on the screen. Every rule it applied was hand-written into
JavaScript, every threshold was a literal, and nothing in it could look anything up. It was a
report that resembled a tool.

The goal for the day was to build the thing the page was pretending to be, without breaking the
part that already worked.

## What got built

### An engine with nothing in it

`analyzer/core/` is pure Python — no framework, no network, no I/O. That is
[ADR 0002](../adr/0002-pure-scoring-core.md), and it is enforced two ways: a test that reads the
source with `ast` and bans the imports, and a CI job that installs the package with **no extras
at all** and runs a full analysis on an interpreter where `fastapi`, `pydantic`, and `httpx` do
not exist. The first check can be fooled by a dependency that becomes load-bearing without
appearing in an import line. The second cannot.

The buyer's constraints live in `buyer_profile.toml`, not in code. Adding a persona — a hospital
employee, a remote engineer, a school-focused family — means copying a file, not editing a
function. That was the single most useful structural decision of the day, and everything later
in this entry depends on it.

### Six source stations, one failure contract

`analyzer/sources/` — geocoding, parcel, flood, commute, broadband, and the shared HTTP layer.
Each obeys the same contract from [ADR 0006](../adr/0006-source-station-contract.md): **never
raise, never guess.** A station returns data or it returns a documented degraded state. It does
not substitute a plausible number.

That contract earns its keep immediately, because two of the six are degraded on any given day:

| Source | State | Why |
|---|---|---|
| Census geocoder | Working | — |
| FEMA NFHL flood layer | Working | — |
| OSRM routing | Working | — |
| Nominatim | Working, throttled to 1.1s | Usage policy |
| Spartanburg County parcel data | **Mirror from Feb 2021** | The county's live server has a broken TLS certificate chain |
| FCC broadband map | **Unavailable** | Returns 401 without an API key |

On the parcel server: the fix that would have "worked" was disabling certificate verification.
That was rejected. A stale-but-honest mirror with a documented date is a better artifact than
fresh data obtained by turning off a security check, and the report labels every parcel figure
with its vintage.

### Three doors, one engine

A CLI for one address, a batch runner for a CSV shortlist, and a localhost-only FastAPI service
in a container. All three call the same core, which is
[ADR 0007](../adr/0007-http-service-container-and-split-ci.md).

The temptation here is to let each door grow the little helper functions it needs. That is
precisely how a codebase ends up with two implementations of the same scoring that agree on
Tuesday and disagree by Friday. Instead the shared functions were refactored so the door is
genuinely thin: `read_shortlist(path)` wraps `parse_shortlist_text(text)`, `write_summary_csv`
wraps `write_summary_stream(result, handle)`, `write_markdown` wraps `render_markdown(result)`.
The API streams; the CLI writes files; neither owns any logic.

There is a test class called `TestDoorsAgree` that compares HTTP response bodies line-for-line
against the CLI's output files. It exists because "they share a core" is a claim, and claims
should be executable.

### A container that means it

Two-stage build, `python:3.12-slim`, non-root uid 10001, multi-arch for amd64 and arm64 so it
runs on the Pi cluster, BuildKit cache keyed by `TARGETARCH`, healthcheck on `/health`. Compose
binds to `127.0.0.1:8000` only, mounts the profile read-only, and caps memory at 512M.

The service is deliberately unauthenticated, which is exactly why it is bound to localhost. That
is a documented decision, not an oversight — see
[KNOWN_LIMITATIONS](../KNOWN_LIMITATIONS.md).

### CI split by what a failure means

Two workflows, and the split is the whole point:

- `tests.yml` runs on every push and contains only what can be verified without depending on
  someone else's server being up. It must be boring. A workflow that goes red because
  Spartanburg County had a bad afternoon teaches people to ignore red builds, and then it stops
  protecting anything.
- `live.yml` runs nightly against the real endpoints, with no retries and no exact-score
  assertions. A failure there means "a source changed, go look" — so it opens or comments on a
  single `source-drift` issue rather than blocking a commit.

The live workflow was run manually to confirm it works end to end: 6 live tests passed and a
full analysis returned `WATCH 52`, matching the local run exactly.

## The bugs

None of these were typos. Each one is a category of mistake worth recognising again later.

### Silence scored as perfection

Two properties with no county parcel record scored a clean **100 TAKE** and outranked a
fully-documented house at 52.

Every deduction was guarded by "if we know this value." Not knowing anything therefore cost
nothing, and the engine rewarded absence of evidence with a perfect score. It was confidently
recommending the two houses it knew the least about.

The fix is an explicit `unknown_facts` list that caps the score below the TAKE threshold, and
the cap is **one-directional** — it can only lower a score, never raise one, so a missing data
source can never make a property look better than it is. The report says which fact was missing
and that the cap applied.

This is the most valuable bug of the day because the code was doing exactly what it said. The
error was in the design: treating "no data" and "no problem" as the same thing.
[ADR 0005](../adr/0005-capital-expenses-deduct-and-unknowns-pin.md) records the rule.

### A default argument froze the world at import time

`analyse_shortlist(runner=run)` bound the network function as a **default parameter**, which
evaluates once at import. Tests that believed they were substituting a fake runner were making
real Census requests — and passing, which is the worst possible outcome. A test that passes for
the wrong reason is more dangerous than one that fails.

Fixed with late binding: default to `None`, resolve inside the call.

### The rulebook walked into site-packages

`load_profile()` located `buyer_profile.toml` by walking up from its own source file. That works
perfectly from a checkout and breaks the instant the package is installed, because the walk then
starts inside `site-packages`.

It bit twice in one afternoon. First the container started cleanly and failed on the first
request. Then it took out roughly 200 CI tests with a `FileNotFoundError`. The fix is an explicit
call-time search order — `$HBA_PROFILE`, then beside the package, then the working directory —
and the container smoke test now calls `/profile` specifically, because `/health` would pass even
with an unreachable rulebook.

### CI was testing a copy of the code

Related, and worse. CI installed the package non-editable, and `pytest` (unlike
`python -m pytest`) does not add the working directory to `sys.path`. The suite was therefore
testing the installed copy in `site-packages`, not the commit under review. Every change would
have needed a reinstall to be tested at all — a very quiet way for CI to stop verifying anything.
Now it installs with `-e`.

### An explicit zero was rejected as missing

`parse_money` refused a value of `0`, so a property with an explicitly-stated $0 HOA was treated
as invalid input. Split into `parse_money` and `parse_optional_money`. Small, but the same theme
as the first bug: conflating "zero" with "unknown."

### A network guard blocked the test runner's own plumbing

The `no_network` conftest fixture blocked socket creation, which also blocked asyncio's internal
`AF_UNIX` socketpair — failing every web test with a message about network access that had
nothing to do with the actual cause. Now family-aware: `AF_INET`/`AF_INET6` blocked, `AF_UNIX`
allowed.

## The drift that had been hiding all day

The last task was meant to be a five-minute check: confirm the published snapshot at
`spartanburg.pplx.app` matched the work.

It did not, and not because it was stale. `app.js` contained a **second, complete implementation
of the scoring rules**, hand-written in JavaScript, predating the engine. Nobody had looked at it
all day. [ADR 0007](../adr/0007-http-service-container-and-split-ci.md) had warned, in its own
words, that two implementations "drift until they disagree about the same house" — and then
counted three doors when there were four.

By the time it was measured, the two disagreed like this:

| Rule | The page said | The engine says |
|---|---|---|
| HOA above $100/mo | score 0, **PASS**, disqualifying | −25, still a candidate |
| Roof at 17 years | a note, no points | −25 |
| Roof at 22 years | a note, no points | −35 |
| HVAC at 14 years | a note, no points | −15 |
| HVAC at 19 years | a note, no points | −22 |
| WATCH floor | 50 | 45 |
| Facts unknown | scored as if the answer were good | capped below TAKE |

Two of those are opposite decisions on real houses:

- **606 Andre Ct** — roof 17, HVAC 14, 2.5 baths, living area not recorded by the county — read
  as a confident **TAKE** on the published page. The engine scores it **52 WATCH**. The page was
  recommending an inspection on a house carrying an estimated $13,500–$33,500 of near-term roof
  and HVAC work, because an aging system produced a sentence instead of a deduction.
- **A house with a $150/mo HOA and nothing else wrong** was rejected outright by the page —
  score 0, PASS. The engine scores it **75 TAKE**. The page was discarding good houses over a
  $50 overage, which is the specific call the HOA rule had been changed to stop making.

Neither is a coding error. The page was correct when it shipped; the profile moved and the page
did not. That is what two hand-maintained copies of the same rules always do.

The browser cannot import Python, so it could not be given the same fix the API got. The rules
are now **compiled**: `tools/build_snapshot.py` reads `buyer_profile.toml` and writes a
declarative rule block into `data.json`, and `app.js` evaluates that block in the same order as
`analyzer/core/scoring.py` — hard fails, deductions, capital expenses, unknown-facts cap, then
verdict bands. Three things hold it:

1. `python tools/build_snapshot.py --check` fails CI when `data.json` goes stale.
2. Tests trace every threshold, weight, and dollar band back to the profile and to
   `analyzer/core/capex.py`.
3. A test asserts `app.js` actually reads `DATA.rules`, that the old hand-written branches are
   gone, and that no bare threshold has reappeared inside the scorer.

Check 3 is the load-bearing one. Checks 1 and 2 would both have passed on the broken version —
correct data sitting beside a function that ignores it is indistinguishable from a working
system. Full reasoning in
[ADR 0008](../adr/0008-browser-rules-are-compiled-not-rewritten.md).

Verified by hand in a browser against `analyze()` on identical facts:

| Case | Engine | Page |
|---|---|---|
| 606 Andre Ct, size unknown | 52 WATCH | 52 WATCH |
| $150/mo HOA, nothing else wrong | 75 TAKE | 75 TAKE |
| All facts known, nothing failing | 100 TAKE | 100 TAKE |
| Roof 22, HVAC 19 — both overdue | 43 PASS | 43 PASS |
| 25-minute commute | hard fail | 0, deal-breaker |

The page also gained a "Run the full engine" section stating plainly what a snapshot can and
cannot do — it scores typed facts and looks nothing up — with the commands to run the CLI, the
batch runner, and the container.

## Decisions worth restating

- **An old house is a caveat, never a deduction.** Build year before 2000 produces a note. Age
  alone is a prompt to look closer, not evidence of a worse house.
- **Three hard fails only:** FEMA flood zone, well or septic, commute over 20 minutes. Everything
  else is survivable and scored.
- **Maintenance reserve reports three methods side by side and never averages them.** Averaging
  three guesses produces one confident-looking number that is worse than any of the three.
- **Broadband is labeled an estimate with an instruction to call the ISP.** FCC data is
  census-block precision; a neighbour's fiber is not your fiber.
- **The commute anchor is Spartanburg Medical Center with a 6:30–7:00am arrival window** — the
  hospital shift change, not generic office peak.
- **The public site stays a snapshot; the real tool is a local container.**
  [ADR 0001](../adr/0001-static-snapshot-plus-local-container.md).
