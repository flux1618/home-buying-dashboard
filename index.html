    The five decisions you actually need to make · in order

    1. Confirm your top-2 submarket by Nov 2026. Rank suggests Boiling Springs (fiber-strong, listings tightening) and Roebuck (best commute + best fiber overlap) as the shortlist. Drive both on a Tuesday 7:30am to prove commute; walk two candidate streets after dark.
    2. Lock down-payment target by Dec 2026. 15% of $310K = $46,500; keep the rest as reserves. If your side income holds at $1,500/mo net, your runway comfortably clears 15% by lease-end. Only push to 20% if the appraisal-gap risk in your top submarket is high.
    3. Get an actual insurance quote in Jan 2027. The $3,102 statewide average understates recent SC increases (+9.7% in 2025). A real quote on a candidate property, before you go under contract, prevents a payment surprise at closing.
    4. Set your rate-lock rule now. Rule: lock any 30-yr rate ≤ 6.75% once you have an accepted offer. Do not wait for a lower print. The plausible 2027 range only moves your payment ~$45/mo.
    5. Trigger buy or wait in Apr 2027 using the timing table. Buy signal: months-supply >5.0 AND YoY price still ≤0. Wait signal: any BMW shift-reduction or Spartanburg WARN filing >500 workers. Otherwise, execute a normal purchase — the odds favor you.
    Discipline note. Protecting capital comes first. Your household has strong income and a specific, near-in-time window. The edge is not predicting price or rate — it is choosing a submarket that fits your commute + fiber + schools rules, and moving decisively when supply and time-on-market look this favorable.

    Run the full engine

    This page is a snapshot on purpose — static files, no backend, no keys, works offline. The analyzer behind it does the part a snapshot cannot: it goes and looks things up.
    What this page does
    • Scores facts you type in, against thresholds compiled from buyer_profile.toml
    • Applies deductions, capital-expense tiers, the unknown-facts cap, and the verdict bands in the same order the engine does
    • Models affordability, rent-vs-buy, and down-payment runway from the sliders
    What only the engine does
    • Geocodes the address, then pulls the county parcel record, FEMA flood layer, and live drive time to Spartanburg Medical Center — so hard fails are looked up, not typed
    • Real property-tax millage with the SC 4% / 6% assessment-ratio reset on sale
    • Full amortisation, insurance proration, cash-to-close, and three separate maintenance-reserve methods reported side by side rather than averaged
    • Scores a whole CSV shortlist at once and ranks it
    • Says clearly when a source was unreachable instead of quietly guessing
    Three doors, one engine. A CLI, a batch runner, and an HTTP API all call the same scoring core — they cannot disagree about a house. This page is the fourth door, and it is the one that can't import Python, so its rules are compiled out of the profile by tools/build_snapshot.py and a CI check fails the build if the two ever drift apart again.
    Run it locally
    git clone https://github.com/flux1618/home-buying-dashboard
cd home-buying-dashboard

# one address, full report
pip install -e '.[api]'
python -m analyzer.cli "606 Andre Ct, Spartanburg, SC 29301" 268000 --roof-age 17 --hvac-age 14

# a whole shortlist, ranked
python -m analyzer.batch examples/shortlist.csv

# or the API in a container, bound to localhost only
docker compose up --build     # then http://127.0.0.1:8000/docs
